# 画像仕様｜fitness-c（AOZORA FITNESS サンプル）

画像を生成・用意していただくための仕様書です。**表示サイズはすべて本番サイト
（https://hp-template-fitness-c.vercel.app）をChromeで実測した値**で、推測値ではありません。
測定幅：375 / 414 / 601 / 768 / 900 / 1024 / 1280 / 1440 / 1920px。

- 生成解像度は「実測の最大表示サイズ × Retina（2倍相当）」を上限に、**引き伸ばしも無駄も出ない値**にしています
- 変換は `python scripts/optimize-images.py` が行います（WebP化・幅違い・ファビコン一式）
- 画像内に**文字・数字・ロゴを描かせない**でください（見出しはすべてCSSで重ねています）

## 4. 画像を入れない箇所（判断と理由）

| 箇所 | 判断 | 理由 |
|---|---|---|
| スタッフ／トレーナー紹介 | **枠ごと設けない**（現状維持） | 架空の人物を実在の人物として提示することになるため。複製元にあったスタッフ紹介（`StaffList`）と顔写真枠は削除済み。信頼感は「入会後1か月のサポート」「定員12名」など具体的な運営内容の記述で担保しています |
| 「はじめての方から、よくお聞きすること」<br>`.issue-card` ×3 | 入れない | `01/02/03` の連番と見出しで構成する設計。写真を足すと連番の視認性が落ち、3枚のカード高さが不揃いになる |
| 「選ばれる理由」`.strength-card` ×3<br>「ひとりでも、みんなとでも」×3 | 入れない | 3カラムのため**768px幅ではカード幅が実測227pxまで縮む**。ここに写真を入れると横長の帯状に潰れて内容が判別できない。文章量も多く、写真は視線を奪うだけになる |
| 料金プラン `.price-card` ×3 | 入れない | 金額と条件の可読性が最優先。写真は情報の判断材料にならない |
| プログラム紹介（`/price` の `.service-section` ×6） | 入れない | `/facility` の設備写真と被写体が重複する。同じジムの写真が2ページに散ると「別の施設に見える」リスクもある |
| 見学・体験の流れ `.flow-list` | 入れない | 各ステップを縦線でつなぐ設計（`.flow-item::before`）。ステップごとに画像を挟むと縦線が途切れ、工程のつながりが読めなくなる |
| よくあるご質問（`details/summary`） | 入れない | 開閉するテキストのため、画像を入れると閉じた状態の一覧性が失われる |
| お問い合わせ／プライバシーポリシー／ご利用について／404 | 入れない | 手続き・規約のページ。装飾写真は目的の達成を妨げる |

## 5. 生成後の受け渡し方

1. 生成した**PNG**（またはJPEG）を、上の「配置先」のファイル名で `public/images/` 以下に置く
2. `python scripts/optimize-images.py` を実行（WebP化・幅違い・ファビコン一式が生成され、元画像は `image-src/` へ退避されます）
3. 実機での崩れ確認・`OGP_TEXT` の修正・`WEBP_JOBS` への追記・pushは、こちらで対応します

> 元画像は**縮小のみ**行われます。指定より小さい画像を渡すと、その幅の書き出しが飛ばされて
> 参照側と食い違い404になります。**推奨解像度以上**で生成してください。
