### 画像追加にあたって行った変更

| 変更 | 理由 |
|---|---|
| 下層4ページに見出しバンドを追加（`Layout` の `hero` に `SectionBand`） | 用意された3:1の帯が6枚あり、トップだけでは使い切れないため。文字は重ねず装飾として使用 |
| `main:not(.main--full) > .section-band:first-child` に `margin-top:-40px` | `main` の上余白40pxを打ち消し、ヘッダー直下から全幅で見せるため。**左右方向には負のマージンを使っていない**（横スクロールの再発を避けるため） |
| 施設カードを `.facility-card` として新設（`.program-card` とは別クラス） | `.program-card` は600px以下で padding が 28/24→20/16 に変わる。負のマージンで画像を端まで出す作りにすると、この差ではみ出し量がずれて横スクロールの原因になる。カード側の padding を0にし、文章側（`.facility-card-inner`）に持たせて負のマージンを使わずに解決した |
| OGPの暗幕の最大不透明度を 95→158 に変更 | 背景の白壁に白文字が沈み、実測コントラスト比が2.4:1程度になっていたため。変更後は**6.4〜8.6:1**（実測） |
| `OGP_TEXT` を AOZORA FITNESS の文言に変更 | 複製元（NAGI COFFEE）のままだったため |
| ロゴの余白を15.7%→8%にトリミング | 16pxのファビコンで図形が小さくなりすぎるため |

## 6. トラブル事例と再発防止策

| 事例 | 再発防止策 |
|---|---|
| ローカル検査を `file://` で行い、CSSが当たっていない状態のスクリーンショットを見ていた | 静的書き出しの検査は必ずHTTPで配信して行う（`/_next/...` は絶対パスのため `file://` では解決できない） |
| 検査用ポート（4321・4399）が別プロジェクトのサーバーに使われており、他サイトを検査していた | 検査の最初に、配信中のHTMLへ屋号（`AOZORA FITNESS`）が含まれるかを `curl` で確認してから計測を始める |
| `.cta` の負のマージンが panel の padding 依存だった | 負のマージンを使う箇所は、依存する padding と同じ値であることをコメントに明記し、適用対象を限定する |
| 複製フォルダに `.git` がなく、手順書の「Git履歴を作り直す」がそのままでは通らなかった | `.git` の有無を先に確認し、無ければ `git init -b main` から始める（手順書は複製元の `.git` が残っている前提だった） |
| `vercel link` が `.env.local` に `VERCEL_OIDC_TOKEN` を書き込み、`.gitignore` に `.env*` を追記した | 想定どおりの動作。`.env*` の行はVercel CLIが管理するものとして残す（消すとトークンが誤ってコミットされうる） |
| 検査用のローカルサーバー（`python -m http.server`）が検査の途中で落ち、以降のページが `ERR_CONNECTION_REFUSED` になった | 単一スレッドのため、ブラウザが接続を打ち切ると落ちることがある。検査用サーバーは `ThreadingHTTPServer` を使い、リクエスト処理の例外を握りつぶす簡易サーバー（`scratchpad/serve.py`）で立てる |
| 画像パスをデータへ一括追加した際、`slug` が同名の別データ（`PROGRAMS` の `machine`）にも紛れ込んだ | 一括置換でデータを更新したら、置換件数を数えて期待値と突き合わせる（今回は6件のはずが7件で気づいた） |
| lazy読み込みの画像が「未読込」と検出された | 折りたたみ下の画像は `loading="lazy"` のため、スクロールせずに判定すると未読込に見える。画像の検査は要素までスクロールしてから判定する |
